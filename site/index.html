See what Claude Code is doing — live, in a pane beside it.

cctop is an htop/btop-style terminal dashboard for a running Claude Code session. It shows the internals Claude Code doesn't — context fill and when the next compaction hits, tokens and cost with cache-hit ratio, rate limits with an exhaustion forecast, what the current turn is waiting on, per-tool latency and how much context each tool pushed, subagents and MCP servers, touched files — on one page, in real time, in a right-hand split while you keep working on the left.

brew install tomstagl/tap/cctop

or cargo install cctop · then claude plugin add tomstagl/cctop and type /cctop

Claude Code keeps running on the left; cctop follows it from the right. Everything is live.

narrow layout · 60 columns · the right-hand-pane case. At ≥ 100 columns the panels flow into two columns.

What each panel answers

1 Context

How full is the window, how fast is it filling, how many turns until autocompact

2 Tokens & Cost

Cache read / write / fresh / output / thinking, cache-hit ratio, $ and burn rate

3 Limits

5 h and 7 d usage, reset countdown, will I run out before the reset

4 Turn

What the turn is doing right now, API vs tool time, hook overhead, permission waits

5 Tools

Calls, errors, p50/p95, and tokens each tool pushed into context

6 Agents & MCP

Subagents, MCP server processes, background tasks

7 Files

Blast radius and wasted re-reads

8 Events

Tool / hook / permission / compaction / note stream

9 Advisor

One evidence-backed recommendation at a time, ranked by tokens saved

One recommendation at a time

The Advisor turns what it sees into a single concrete change, ranked by what it saves. Eighteen deterministic rules; no model call, no network. Three examples from real sessions:

▸ `Bash ls -R` pushed 4.4k tokens into context, 2×
Pipe through `head -50`, use Glob/Grep, or ask a subagent for a summary. ~8.8k/turn · A03
▸ Prompt cache expired before turn 12
Batch your questions or keep the session warm; each cold turn re-writes the whole context (TTL 1 h on this session). ~396k · A02
▸ mcp:playwright has had no calls for 42:00
Disable it for this project (.mcp.json) or rely on deferred tool loading. ~3.1k/turn · A07

Ask your session about any of them: the bundled cctop-insights skill answers from cctop query.

Install & attach

brew install tomstagl/tap/cctop     # or: cargo install cctop
claude plugin add tomstagl/cctop    # adds /cctop and cctop-insights
/cctop                              # opens the dashboard in a right-hand pane

Optional: exact rate limits and tool timings

cctop install wraps your status line with a tiny shim and registers cctop hook for Claude Code's hook events. It shows a diff of ~/.claude/settings.json, backs the file up to ~/.cctop/backups/, and asks before writing. cctop uninstall restores the original. Without it, every panel still works from the transcript alone.

Local only

cctop reads ~/.claude (session registry, transcripts, hook events) and the process tree, and writes only under ~/.cctop and ~/.config/cctop. It sends nothing over the network. Cost figures for subscription plans are API-equivalent list prices, marked ≈.
