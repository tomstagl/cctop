# Mod Pane Implementation Plan (PRD 9)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The pane redrawn with Claude Code 2.1.332 mods from the approved POCs: full, plain-language, actionable coach advice (POC 1); the overview with verdict-bearing charts (POC 6) drawn as pictures where the terminal can (POC 7, Ghostty) and as cells where it can't (POC 8, Terminal.app); the act dialog (POC 5) and placed transcript rows (POC 4); the TUI drawing the same objects as text.

**Architecture:** One state, two renderings. Rust builds the words (`coach.rs` full fields) and the charts as data (`src/overview.rs` + `src/verdict.rs`). One chart crate, `crates/cctop-charts`, renders a spec as cells (linked natively into the TUI) or as a PNG (compiled to `plugin/hooks/charts.wasm` and run by the pane with `$.wasm.compile`). The pane decides picture or cells per session.

**Tech Stack:** Rust (workspace; tiny-skia, png, insta), WebAssembly (wasm32-unknown-unknown), TypeScript function hooks (2.1.332 d.ts), `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-26-cctop-mod-pane-design.md` and `tasks/prd-cctop-mod-pane.md` (PRD 9). Design sources: `tasks/design-mod-pane/` (POCs 1–8).

## Global Constraints

- Branch `mod-pane`, cut from `otel-traces` after PRD 7. Commit subjects `Coach: …`, `Charts: …`, `Pane: …`, `Docs: …`, trailer in the body.
- **Read-only:** no `$.turn.abort` anywhere (grep test); fill never sends; cctop never edits settings.json (copy + open only); placed rows are display only (no `session.append`).
- **No prose:** no string from the person's or the model's text in any coach field; evidence and fix prompts use fixed labels per error class, never quoted tool output.
- **Pane rules (CLAUDE.md):** `$` only into top-level functions / facades; literal `$.env.get("…")`; literal `$.wasm.compile('./charts.wasm')`; no local `h`/`Fragment`; validator `--strict` clean with 0 `error TS`.
- **No text inside any picture**; labels are terminal text beside whole-cell-placed charts.
- **Identical characters:** the TUI's chart cells equal the pane's Raster cells (same `render_cells`); one-line forms keep the 52-cell cut (`coach::WIDTH`), full fields are uncut.
- **Wasm:** `plugin/hooks/charts.wasm` committed (the one build output under `plugin/`), < 600 KB, memory max 64 MiB, freshness by inputs hash, PNG per chart < 2 MiB, < 30 ms per chart render.
- **Toolchain:** this machine has Homebrew rustc 1.85 without rustup. The user chose an isolated rustup at `~/.cctop-toolchain` (RUSTUP_HOME=`~/.cctop-toolchain/rustup`, CARGO_HOME=`~/.cctop-toolchain/cargo`, stable + wasm32-unknown-unknown). `make wasm` uses it when present (`WASM_TOOLCHAIN ?= $(HOME)/.cctop-toolchain`), else plain `cargo` (CI, rustup on PATH). Never touch the user's PATH or shell config.
- **Degrade by presence:** every PRD 1–7 element hides when its data is absent; fixtures without that data move no snapshot.
- Fixtures: "fixture C" in the spec means `fixtures/session-r.jsonl` (PRD 1). Insta, generated docs, `scripts/pane-fixtures.sh` per CLAUDE.md.
- **Verification items:** 39–46 are taken. This PRD's live checks are renumbered: 47 Ghostty pictures, 48 Terminal.app cells, 49 tmux with/without passthrough, 50 fill → Enter, 51 Esc hint first + Esc stops with marker, 52 act dialog keys, 53 placed rows scroll / gone after `--resume`, 54 hover readouts — all `Result: pending`.
- Done per task: `make check`, `npm run typecheck`, `npm test`, validator clean.

## Rulings made while planning

- **The words are drafted, then reviewed:** the builder drafts every rule's name/body/fix_prompt/actions/foot and the verdict thresholds (grounded in `tasks/research-coach/` and the coach PRD §5); US-013's tables are generated; the user's sign-off happens before release, not during this run.
- **Task order:** words and objects first (Rust, testable without the pane), then the crate, wasm, TUI, then the pane surfaces; US-011's PRD 1–7 contributions are built inside the task that owns each surface, and Task 13 is the presence/absence snapshot sweep.

## Review Focus

1. A session with zero turns / one turn: every chart spec is valid (empty series), verdicts say nothing alarming, no panic, no NaN in forecasts (Task 3 test).
2. wasm compile fails or the file is missing: the pane logs once and draws cells from the query's fallback cells field (Task 8 test).
3. A 300-turn session: per-turn charts show "last N turns", context/spend bucket the whole session, render stays < 30 ms per chart (Tasks 3, 9 tests).
4. A narrow pane (59 body columns): sparkline forms, no overflow, nothing cut mid-word in the coach card (Tasks 9, 10 tests).
5. A NOW nudge of kind `key` while a turn runs: "press Esc to stop the turn" is shown first, and nothing calls `$.turn.abort` (Task 11 grep + test).
