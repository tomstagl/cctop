# Pane on the 2.1.332 API Implementation Plan (PRD 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The pane uses five 2.1.332 APIs read-only: `$.session.info()` (query by transcript path; data-rule badges; screen reader), `$.agent.limits()` (agents header), `$.ui.view({agentId})` (jump to an agent from a press), opt-in `$.ui.notify` (NOW nudges, rate-limit resets), and the `session.stop` event.

**Architecture:** Pane-only facts reach Rust through the pane marker (`~/.cctop/pane/<session>.json`, `poller.ts`) under a new `facts` key; `src/pane.rs` parses it; `dashboard.rs` carries badges and limits to both surfaces. Pure decisions (agent-id mapping, notify bookkeeping, stop) live in `model.ts` / small pure modules with tests.

**Tech Stack:** TypeScript (function hooks, `node --test`), Rust (serde, insta).

**Spec:** `tasks/prd-cctop-pane-apis.md` (issue #30).

## Global Constraints

- Branch `pane-apis`, cut from `hook-events` after PRD 5. Commit subjects `Pane: …`, `Docs: …`, trailer in the body.
- Read-only: never hook `agent.report`; never call `$.theme.*`, `$.agent.call`, `$.session.append`, `$.prompt.compose/paint`, `$.session.identity()`, `$.vcs.*`, `$.ui.place`, `$.ui.selection`, `$.session.machine()`, `$.process.hookEnv()` (PRD 9 adopts `$.ui.place` later; not here).
- Pane rules (CLAUDE.md): `$` only into top-level functions or a facade (`pollerEngine($)` pattern); module state in module-scope `let`s; `$.env.get("CCTOP_PANE_NOTIFY")` spelled literally in `pane.tsx`; no local `h`/`Fragment`; `.catch` failures are `next.error`. Validator `--strict` clean.
- Marker key `facts: { dataRules?: string[], platform?: string, isScreenReader?: boolean, agentLimits?: { concurrent: number, depth: number, isBackgroundEnabled: boolean } }`.
- Data-rule badges: `ZDR` for `zdr`, `HIPAA` for `hipaa`, `rules` for any unknown name (d.ts: absent or unknown = in force).
- Agents header: `<running> / <concurrent> running · depth ≤ <depth>` + `· no background` when `isBackgroundEnabled` is false; unchanged without a marker.
- `$.ui.view` only from `onPress`. Notifications off unless `CCTOP_PANE_NOTIFY` = `1`.
- `session.stop`: observe only; note the stop before any `await`; return `next(e)` unchanged.
- Live checks → `docs/verification/pane.md` `Result: pending` (item 43).
- After dashboard changes rerun pane fixtures; insta and docs per CLAUDE.md. Done = `make check`, `npm run typecheck`, `npm test`, validator clean.

## Rulings made while planning

- **Screen reader:** where the view bar or header draws a glyph-only badge, `isScreenReader` swaps it for its word (the badge's existing text label). If no glyph-only badge exists today, the test asserts the rendered bar contains no glyph-only token under `isScreenReader` and the task reports that nothing needed swapping.
- **Notify "fire id":** the advisor's fire identity as the coach object exposes it (rule id + fire time, or the persisted fire id if the object carries one); key `nudge-<rule id>`.

## Review Focus

1. `$.session.info()` rejects or returns no `transcriptPath` (older engine, unbound session): the poller keeps using the id (Task 1 test).
2. The session id rotates (`/clear`): `info()` is re-read and the poller switches to the new path; the old path is never polled again (Task 1 test).
3. `$.agent.list()` contains two agents of the same `type` and `description`: the spawn-order fallback maps each to a distinct id, never both to one (Task 3 test).
4. Notify returns `no-channel`: no further notify calls this session, including the scheduled reset (Task 4 test).
5. `session.stop` arriving while no turn runs (`isTurnRunning: false`): no state change beyond a poll; never a negative duration (Task 5 test).
