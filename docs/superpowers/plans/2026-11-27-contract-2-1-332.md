# Contract 2.1.332 Implementation Plan (PRD 0)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CI's `contract` job green on Claude Code 2.1.332 without credentials, the checked-in d.ts and every version pin on 2.1.332, the pane passing `claude plugin validate --strict`.

**Architecture:** `/plugin-types` is gone. Two replacements: `scripts/extract-dts.py` reads the core d.ts (no tool tables) out of the `claude` binary's zstd frames, credential-free, for CI's surface diff. `scripts/regen-dts.sh` gets the full d.ts from the bundled `/plugin-authoring` skill (one model call, logged-in), for the release checklist. Then the pane is fixed for `noUncheckedIndexedAccess` and the new `widget` placement, and the pins move.

**Tech Stack:** Python 3 stdlib + `zstd` CLI, bash, TypeScript (Node ≥ 22, `node --test`), Rust (harness facts).

**Spec:** `tasks/prd-cctop-contract-2-1-332.md` (issue #24).

## Review Focus

1. `claude` on PATH is a symlink (`~/.local/bin/claude` → `~/.local/share/claude/versions/2.1.332`): extraction must resolve it, or it scans a 100-byte link. Task 1 tests through the PATH symlink.
2. A frame that decompresses to something else, or a truncated frame (zstd non-zero exit), must be skipped, not abort the scan. Task 1's scan treats every `zstd` failure as "not this frame".
3. `regen-dts.sh` finding several `bundled-skills/<v>/<rand>/` dirs (the skill writes a new random dir per run): it takes the newest by mtime. Task 2 asserts the copied file's line 1 against `claude --version`.
4. CI's npm-installed `claude` may not be the Bun binary: the first PR CI run is the check (Task 4, Step 6), with the fallback named there.
5. A widget-placed pane must lay out exactly like inline (no dock-only width logic applied to it). Task 3's reducer test pins it.
