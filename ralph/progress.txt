## Codebase Patterns
- Native slash command is `/cctop-pane` (`COMMAND` in plugin/hooks/pane.tsx): the engine refuses `$.command.register({ name: "cctop" })` because the plugin's skill already owns `/cctop` (`/cctop:cctop`). Stories that say `/cctop <args>` for the native command mean `/cctop-pane <args>`; `/cctop` alone is the skill.
- `claude -p --debug` writes nothing to stderr; the debug log is `~/.claude/debug/latest` (symlink to the newest `<session>.txt`). Grep it for `hooks module cctop loaded`, `refused`, `hook failed`.
- TS toolchain: `typescript` is the only devDependency and tsconfig has `types: []`, so `node:test` / `node:assert/strict` are declared by hand in `tests/pane/node.d.ts` (extend it when a test needs another assert method). `npm test` compiles with tsconfig.test.json (commonjs + esModuleInterop, outDir `.test-build`) and runs `node --test '.test-build/tests/pane/**/*.test.js'` (a bare directory arg is not a glob in Node 22).
- In a `.catch` handler the failure is `next.error` (`{ kind, message?, budget }`), not a `failure` field; there are no `$.ui.*` element globals, always `const { Text } = $.ui.resolve(e)`.
- `claude plugin validate --strict ./plugin` prints the hooks and `$` calls it found in the module; use it to confirm the engine sees the events you meant.
- Render tests: import `tests/pane/harness.ts` first (it installs the JSX globals `h`/`Fragment` the compiled module calls), build the event with `paneRender(id, columns)`, dispatch `ui.render` through `fakeOn($)`, and flatten with `renderToText(tree, columns)` (`tests/pane/render.ts`: row/column Boxes, width/flexGrow/padding, Text wrap/truncate, `[hotkey label]` Buttons). Fixtures load with `fixture('summary')` from `tests/pane/fixture.ts`; `scripts/pane-fixtures.sh` regenerates the query ones.
- `claude plugin validate --strict` refuses `$` handed to any function that is not a top-level declaration of the module (`$ is passed to "apply", which is not a function declared at the top of this file`): keep module state in module-scope `let`s and write `$`-taking helpers as top-level `function`s; `register` resets the state.
- The validator follows `$` only into top-level functions of the same file, never across an import: a helper module that needs the engine takes a facade type (a `Pick` of the `$` nouns it uses) built by a top-level function in pane.tsx (`pollerEngine($)`); `$.env.get` needs its literal name in pane.tsx too. The fake `$` is structurally assignable to such a facade. Also: `fakeEngine` copies `opts.process` at construction, so a test that changes answers later writes to `$.process.script`.
- In a `.tsx` module never name a parameter or local `h` (or `Fragment`): JSX compiles to calls of the global `h`, and a shadowing binding typechecks fine but fails at run time with `h is not a function`. Views take `Pick<ElementTable<'terminal'>, 'Box' | 'Text'>` built from `$.ui.resolve(e)` in pane.tsx; tests hand them `fakeElements(new Map())` and walk the tree for `key`/`wrap`/`color` props.
- Detail-view tables come from `row(cells, el, key)` in views/table.tsx: fixed cells carry `width` + flexShrink 0 and the one cell without a width shrinks first, so budget the fixed widths to leave it ≥ 14 columns at 50; `key` on a Text/Box is the metric id, and the same key on sibling rows is harmless (the d.ts says a duplicate merely names no hover scope). Long prose (Advisor `explain`) is pre-wrapped with `wrapWords` into one truncating Text per line, since every Text must truncate.
- The harness draws a Button as `[1 Label]` (one column wider than the engine's `plain` form `1: Label`): a hooks-module layout that budgets Button widths must use the wider figure or the width tests fail while the engine would fit. Button `key` is the press address (`$.ui.press(key)` in tests; defaults to the label), and `$.store` content is the way a test reads module-private state such as `model.view`.
- The engine's `hooks module cctop loaded ... events:` debug line names engine events only: a hook on an op-event (`ui.close`, `fs.write`, …) is accepted by the validator and raises no `refused` line, but does not appear there, so its firing is a live check, not a headless one.
- A Rust-side reader of a timestamp the TS pane wrote (`new Date(...).toISOString()`) should reuse `src/metrics/cost::parse_ts_ms` (the only ISO-8601 → epoch-ms parser in the crate) rather than adding a chrono dependency or a second parser; there is no formatter counterpart, so tests that need a marker fixture hand-write the ISO string and pass a matching `now_ms` rather than round-tripping through one.
- `cargo fmt --all` picks up drift that accumulated in a file across earlier stories that only touched it lightly (rustfmt reformats the whole file, not just the diff); when a later story becomes the one to substantially edit that file, folding the drift into that story's commit is simpler than leaving `make check` red for a future story to discover.
