## Codebase Patterns
- Native slash command is `/cctop-pane` (`COMMAND` in plugin/hooks/pane.tsx): the engine refuses `$.command.register({ name: "cctop" })` because the plugin's skill already owns `/cctop` (`/cctop:cctop`). Stories that say `/cctop <args>` for the native command mean `/cctop-pane <args>`; `/cctop` alone is the skill.
- `claude -p --debug` writes nothing to stderr; the debug log is `~/.claude/debug/latest` (symlink to the newest `<session>.txt`). Grep it for `hooks module cctop loaded`, `refused`, `hook failed`.
- TS toolchain: `typescript` is the only devDependency and tsconfig has `types: []`, so `node:test` / `node:assert/strict` are declared by hand in `tests/pane/node.d.ts` (extend it when a test needs another assert method). `npm test` compiles with tsconfig.test.json (commonjs + esModuleInterop, outDir `.test-build`) and runs `node --test '.test-build/tests/pane/**/*.test.js'` (a bare directory arg is not a glob in Node 22).
- In a `.catch` handler the failure is `next.error` (`{ kind, message?, budget }`), not a `failure` field; there are no `$.ui.*` element globals, always `const { Text } = $.ui.resolve(e)`.
- `claude plugin validate --strict ./plugin` prints the hooks and `$` calls it found in the module; use it to confirm the engine sees the events you meant.
- Render tests: import `tests/pane/harness.ts` first (it installs the JSX globals `h`/`Fragment` the compiled module calls), build the event with `paneRender(id, columns)`, dispatch `ui.render` through `fakeOn($)`, and flatten with `renderToText(tree, columns)` (`tests/pane/render.ts`: row/column Boxes, width/flexGrow/padding, Text wrap/truncate, `[hotkey label]` Buttons). Fixtures load with `fixture('summary')` from `tests/pane/fixture.ts`; `scripts/pane-fixtures.sh` regenerates the query ones.
